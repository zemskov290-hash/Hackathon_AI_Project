# Пересмотр по новым данным

Не переписывай стратегию целиком.

1. `add-source` и `add-evidence` для нового материала. Новая таблица — новый `analyze`, не правка `result.json` руками: `check` пересчитает старый снимок и поймает расхождение. Файлы `*.jsonl` руками и через `python -c` не правь.
2. Если новая запись заменяет старую: `python scripts/strat.py supersede <проект> E015 --by E019 --reason "..."`. Если старое просто неверно, `retract`, не замещение.
3. Сначала узкая метка, какие id новость затрагивает. Это дешевле сильного разбора:

```text
python scripts/strat.py classify <проект> --task impact --input-file новость.txt
```

`label` — существующие id или `none`. Чужой id команда не примет. Затем `python scripts/strat.py impact <проект> <S..|E..>` по этим id: список свидетельств и строк, включая цепочку `depends_on`. `none` значит граф не открывай и стратегию не переписывай.

4. Поправь только эти строки в markdown. Спорное оставь противоречием, не усредняй.
5. `check` до ответа человеку. В ответе не пересказывай числа: либо в том же предложении `[E014]` или `[S003]`, либо только файл и id, без цифры. `**E014**` и `(E014)` ссылкой не являются. Черновик ответа прогони `reply-check` и не отправляй, пока он не напечатал OK. Ответ без чисел допустим. Если рекомендация сдвинулась, не меняй контрольную точку сам. Пересмотр бывает одного из двух видов, и CLI сам дописывает вид в `decisions.md`.

Смена варианта — другой `O…`, чем уже выбран:

```text
python scripts/strat.py propose-revision <проект> --decision D2 --choice O3 --reason-file причина.txt
```

Тот же вариант, но меняются порог, срок, обязательство или `revisit_if`. В файле UTF-8 по одной строке на изменение:

```text
python scripts/strat.py propose-revision <проект> --decision D2 --choice O2 --changes-file изменения.txt --reason-file причина.txt
```

Тот же вариант без такого списка команда не записывает: это не пересмотр. На Windows PowerShell 5.1 кириллицу не клади в аргумент. Один JSON в stdin:

```powershell
@'
{"decision":"D1","choice":"O2","reason":"порог из брифа не выполнен","changes":["порог: не ниже новой планки","revisit_if: пересмотр, если метрика ниже нового порога"]}
'@ | python scripts/strat.py propose-revision <проект> --json -
```

`status` пишет вид и перечень. Человек принимает `accept-revision` или отклоняет `reject-revision`. Оба вызова работают для смены варианта и для условий. Сам выбор не подставляй.
6. `log` с основаниями до любого `advance`. Дату в `decisions.md` не стирай: допиши, что пересмотр случился раньше условия, и почему.

Класс `revise` — уровень `strong`:

```text
python scripts/strat.py complete --tier strong --project <проект> --prompt-file пересмотр.txt
```

`MODE: manual` — разбор пишет модель подписки. В `log` передай `--input-chars` и `--output-chars`, если отвечала подписка. Оценку в `--cost` не подставляй. Затем `python scripts/strat.py cost <проект> --estimate`. Готовый шаг из `resume` не повторяй.
