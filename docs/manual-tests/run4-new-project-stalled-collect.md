# Ручной прогон 4. Новый проект застрял на сборе

Дата: 2026-11-04. Среда: Windows, Cursor Agent CLI. Новый проект `travel-esim` с нуля. Четыре хода со стороны менеджера продукта, около 5,5 минут.

## Что получилось

Бриф с уточняющими вопросами был уместным. На провокацию «просто снизить цены» агент ответил по делу, а не согласился сразу. Папки `scripts/` и `tests/` он не менял.

## Дефект

Агент остался на этапе 3, сбор, с нулём свидетельств. Он ни разу не искал открытые источники сам: не было ни веб-поиска, ни чтения страниц. Все три хода подряд он просил менеджера прислать тексты жалоб, тарифы и страны.

На «покажи варианты» и «дай план проверки на 4 недели» агент отказывал: метод не позволяет. Для менеджера это тупик. Для демонстрации хода от запроса к вариантам это провал: открытые витрины и отзывы можно было собрать без внутреннего архива.

## Что изменено в правилах

Сбор без материалов человека — это desk research: поиск и чтение открытых страниц, выдержка в `sources/`, `add-source --kind web` с URL и датой, дословные цитаты. Цель — 5–8 источников, прежде чем спрашивать человека. Ему остаются только вопросы про внутренние данные и ограничения. Если веб-инструмента нет, агент говорит об этом и предлагает синтетического респондента с пометкой synthetic.

Ранние варианты и план проверки не отклоняются фразой «метод не позволяет». Черновик помечается «гипотезы, не подтверждены, свидетельств N» и `<!-- preliminary -->`, с тем, какие данные вариант подтвердят или убьют. Контрольные точки при этом не закрываются. `check` требует эту пометку, пока этап 5 не открыт.
