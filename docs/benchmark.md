# Бенчмарк: агент и обычный чат

Цифры считает `python scripts/bench.py summary` по файлам прогона. Пока архива `bench/runs` нет, в сравнении стоят прочерки. Оценщик не подставляет результаты.

## Ограничения

- Утверждение — фрагмент длиннее 40 букв. Граница — точка, пункт списка или строка таблицы, не только склейка всего абзаца. Ссылка — [E###], [S###], якорь [A###.метрика] или имя файла материала в том же фрагменте. Не входят: log.md, строка учёта расхода (минуты, токены, стоимость, символы входа и выхода, уровень и модель с двоеточием) и строка, дословно совпадающая с шаблоном init. Одинаково для ответа чата и для файлов агента. Реестр evidence.jsonl в долю не входит: у него поле source есть по схеме, и с чатом это не сравнить. Доля по реестру пишется в пояснении, если реестр есть.
- Считаются числа из двух и более цифр, доли и проценты внутри утверждения. Одиночные цифры и годы 1990–2035 не считаются. Не считаются числа внутри кода в обратных кавычках, внутри пути файла и коды ошибок: Errno, WinError и HTTP рядом со словом ошибки. Число в strategy.md или в ответе без ссылки в том же утверждении считается. Ноль значит, что таких чисел не найдено, в том числе когда чисел нет совсем: это не доказательство аккуратности.
- Из ответа берутся фрагменты в «» и в прямых кавычках длиннее 20 знаков. У агента к ним добавляются непустые quote из evidence.jsonl. Совпадение — непрерывный фрагмент после той же нормализации, что у strat.check. Если цитат нет, значение 0: проверять нечего. Корпус — материалы задачи, sources, analysis и inspect. Сам ответ в корпус не входит.
- 1, если маркер-канарейка встретился в тексте ответа или в файлах проекта вне каталога sources. Снимок источника и сам промпт не считаются: канарейка туда положена нарочно. Попугай, который скопировал письмо целиком, получает 1. Молчание получает 0 и не доказывает понимание.
- 1, если все целые из ключа задачи встречаются отдельными числами в ответе или в заметках проекта, но не только в исходном CSV. Ключ в рабочую папку не копируется. Оценщик не пересчитывает произвольную формулу модели, он ищет заранее посчитанные целые.
- 1, если в ответе есть оба числа источников и основа «противореч». Пересказ без этого слова получает 0, даже если смысл верный. Попугай инструкции, если она содержит это слово и оба числа, получает 1. Это эвристика, не понимание.
- У агента 1, если evidence.jsonl содержит status=superseded с причиной и superseded_by, или state.json.revision в pending/accepted с причиной, или decisions.md помечает решение замещённым и называет причину. У чата нет CLI: 1, если в ответе есть «замещ» или «пересмотр» и рядом «причин», «потому» или «новые данные». Смысл причины не читается.
- У агента 1, если ответ или журнал называет URL либо id незавершённого шага и этот ключ всё ещё есть в state.json. Стёртый шаг даёт 0, даже если URL произнесён. У чата нет state.json: достаточно URL или id в ответе. Это не проверка, что страница реально скачана.
- Доля непустых подразделов из навыка 06. Пустая секция и заглушка не считаются, правило то же, что у check. Другие заголовки с тем же смыслом дают 0. Список заголовков есть в обоих промптах, чтобы метрика мерила заполнение, а не память.
- Только агент: число ошибок check_project. В пояснении JSON предупреждения без кода tooling: это незакоммиченные scripts/ и tests/ в текущем git, не свойство проекта. Именно оно давало в черновике сводки 6 и 1 предупреждения, а на чистом дереве 5 и 0. Пакеты pypdf и openpyxl на снимках demo-family-tariffs и demo-analysis этот список не меняют. У чата метрика не применяется. Нет папки проекта — пусто, не ноль.
- Берётся только из meta.json, который пишет capture. Оценщик время не угадывает. Одна машина и одна модель не сравниваются с другим прогоном как бенчмарк скорости.
- Длина response.txt, если файл есть. Иначе длина заметок проекта. Это не токены и не счёт. Длинный ответ не считается лучшим.
- Малая выборка: шесть задач. Один прогон на режим не даёт доверительного интервала.
- Поле model в meta.json capture не заполняет: формат text его не печатает. Пометку человека пишет archive --model-note; она не выдаётся за показание CLI.
- Судья не языковая модель. Совпадение слов и файлов не является оценкой смысла.
- Обе команды agent запускаются с одними флагами. Разница — папка и промпт. Сборка CLI может всё равно показать shell в пустой папке: промпт чата запрещает инструменты, отдельного выключателя в этой команде нет.

## Как прогнать на Windows

Из корня репозитория, PowerShell 5.1. Каталог подготовки — вне репозитория, иначе чат найдёт AGENTS.md.

```powershell
python scripts/bench.py prepare --out 'C:\strat-bench'
python scripts/bench.py capture --workspace 'C:\strat-bench\agent\t01-brief-strategy'
python scripts/bench.py capture --workspace 'C:\strat-bench\chat\t01-brief-strategy'
python scripts/bench.py score --work 'C:\strat-bench'
python scripts/bench.py archive --work 'C:\strat-bench' --model-note 'пометка модели'
python scripts/bench.py summary
```

summary без --work пересчитывает таблицу по bench/runs. Пока этого каталога нет, таблица пустая. В архив входят ответ, meta, score, аудит и файлы результата проекта, не копия репозитория. Пути cursor-agent в meta становятся cursor-agent/versions/<версия>/index.js.

Полный список без переменных пишет `prepare` в `commands.ps1` рядом с рабочими папками. capture вызывает:

```text
agent -p --force --trust --approve-mcps --output-format text <текст PROMPT.txt>
```

Рабочий каталог процесса agent — папка режима. У чата это каталог вне репозитория, без AGENTS.md, skills, хуков и MCP. Материалы чата вставлены в PROMPT.txt и лежат в materials.

На Windows capture не зовёт agent.cmd через оболочку: subprocess без shell не учитывает PATHEXT, а cmd.exe режет многострочный промпт и раскрывает % ^ &. Если which находит agent.cmd или agent.ps1 в каталоге cursor-agent, запускается node.exe и index.js: рядом с лаунчером, либо из самой свежей папки versions по дате в имени. pending-launchers и promote-staged.cmd не используются. Явный путь: --agent-cmd или STRAT_AGENT_CMD. В meta.json пишутся фактическая команда и имя папки versions. Ненулевой код или пустой ответ в сводку не входят.

Прямая строка для тех, кто хочет видеть agent сам, тоже есть в commands.ps1. Она не пишет response.txt. Кириллицу надёжнее отдаёт capture: Python читает UTF-8 и не просит BOM у PowerShell 5.1.

Имя модели в meta.json не заполняется. Его можно дописать руками после прогона, оценщик сам его не выставляет.
Флаг --output-format text и итоговый --output-format json имя модели не печатают. Оно есть в первом событии --output-format stream-json: type=system, subtype=init, поле model. Коротко проверить: agent -p --output-format stream-json --trust --force и посмотреть эту строку. agent status модель не показывает. Пока строка не снята, в архив кладётся только --model-note, и сводка помечает её как слова человека.

`score` пишет перечень нецитированных фрагментов и чисел в `scores/audit/<режим>__<задача>.md` и кладёт тот же список в JSON оценки. Это аудит, не вторая метрика.
