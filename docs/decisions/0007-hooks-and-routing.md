# ADR 0007. Хуки включены, маршрут моделей явный

- Статус: принято
- Дата: 2026-11-17

## Контекст

Скрипты в `hooks/` уже умели напомнить про `check`, но не были подключены: не было `.cursor/hooks.json` и `.claude/settings.json`. `complete` умел звать дешёвую или сильную модель и без ключа печатал `MODE: manual`, но ни один навык его не вызывал. Длинный `fetch` при обрыве не знал, какой URL уже снят, а страница с HTTP 503 (как T2 в демо) не оставляла в состоянии проекта отдельной записи о провале. Оценка `cost --estimate` пустела, если агент не передавал `--input-chars` и `--output-chars`.

## Решение

Хуки подключены в формате Cursor (`.cursor/hooks.json`) и Claude Code (`.claude/settings.json`). `failClosed` не ставится.

Документация Cursor ([Hooks](https://cursor.com/docs/hooks)) пишет, что проектный хук запускается из корня репозитория, путь вида `.cursor/hooks/script.sh` считается от этого корня, а в окружении всегда есть `CURSOR_PROJECT_DIR` и `CLAUDE_PROJECT_DIR`. На Windows команда идёт через PowerShell. Живой `agent.ps1` это нарушил: рабочий каталог был `C:\`, и `python hooks/guard_shell.py` искал `C:\hooks\guard_shell.py`. Относительный путь, даже `.cursor/hooks/run.py`, при таком каталоге тоже не откроется.

Команда и в `.cursor/hooks.json`, и в `.claude/settings.json` не зависит от каталога. Это `python -c "import base64;exec(base64.b64decode('...'))" <имя>`. Читаемый текст — `PROGRAM` в `hooks/launcher.py`. В json лежит только его base64: внутри нет кавычек, `$` и `%`. PowerShell 5.1, которым пользуется Cursor, вырезает двойные кавычки, когда передаёт аргументы в `python.exe`. Если вставить программу как есть, она превращается в SyntaxError, хук выходит с кодом 1 и сторож молча пропускает команду. `python hooks/launcher.py` заново записывает оба конфига; тест падает, если blob не совпадает с файлом. Посмотреть текст blob: `python -c "import base64; print(base64.b64decode('ВСТАВКА').decode())"`. Программа читает `CURSOR_PROJECT_DIR` и `CLAUDE_PROJECT_DIR` из окружения процесса, затем `workspace_roots` и `cwd` из JSON на stdin, и поднимается к `AGENTS.md`. Если корня нет, наружу уходит `{"permission":"allow"}` для сторожей и `{}` для остальных, код 0.

Cursor с включённым импортом чужих конфигов исполняет оба файла ([Third Party Hooks](https://cursor.com/docs/reference/third-party-hooks)): все подходящие хуки запускаются, а при расхождении отказ побеждает разрешение. Приоритет слияния: Enterprise, Team, проектный `.cursor/hooks.json`, пользовательский `~/.cursor/hooks.json`, затем Claude `.claude/settings.local.json`, `.claude/settings.json`, `~/.claude/settings.json`. Поэтому сломанная команда в `.claude/settings.json` блокирует ход раньше, чем отработает свой хук Cursor. Оба файла зовут один и тот же скрипт и возвращают одно решение; второй `stop` не дописывает журнал, пока первый держит короткую блокировку. Внутренний сбой скрипта ход не блокирует.

- `afterFileEdit` и `postToolUse` для записи файла в `projects/<проект>/` запускают `strat check` и показывают ошибки. Ненулевой код проверки не становится ненулевым кодом хука.
- `beforeShellExecution` отклоняет запись `.env`, чтение секрета в контекст, `git add` ключей и команду, которая дословно нашлась в снимке `sources/`. `beforeReadFile` не отдаёт модели `.env` и файлы ключей. `.env.example` не секрет.
- `stop` дописывает журнал. Транскрипт накопительный, поэтому в журнал идёт прирост символов, модель `hook/stop`. Ответ хука — пустой JSON, без `followup_message`, чтобы ход не зацикливался.
- Если скрипт падает, наружу уходит код 0 и для хуков разрешения валидный `permission: allow`. Блокировка только явным отказом. Правило в `AGENTS.md` при этом не отменяется.

Маршрут лежит в `config/routing.json`. Извлечение и сжатие источников — `cheap`, варианты, критик и стратегия — `strong`, бриф и разговор с человеком — `ide`. Навык вызывает `complete --tier`. Без ключа или для `ide` ответ `MODE: manual`, сеть не вызывается. Удачный ответ API пишет в журнал уровень, модель, токены и стоимость, если её прислал провайдер. Оценка по таблице цен в поле `cost` не кладётся: это по-прежнему допущение ADR 0006.

Шаг в `state.steps` хранит id, статус и хеш входа. `resume` говорит, какой шаг начат и не закончен. `fetch` не качает URL повторно без `--force`. Сеть для 429 и 5xx повторяется с паузой; после последней неудачи шаг `failed` и в журнале есть код ответа. Повторный `add-evidence` с тем же активным type, source, claim и quote отклоняется.

Навыки велят передавать `--input-chars` и `--output-chars` в `log`. `cost --estimate` считает оценку. Строки `hook/stop` в эту оценку не входят, если агент уже записал свои символы, чтобы один ход не посчитался дважды.

## Последствия

Боевой проект в Cursor получает проверку и сторож без отдельного копирования примера. Правка самого репозитория вне `projects/` проверку не запускает. Хук может пропустить команду, если упадёт: агент всё равно не исполняет команды из источников. Имена моделей остаются в `.env` и в репозиторий не попадают. Условные цены `cheap` и `strong` в `config/model-prices.json` нужны только оценке, не счёту.
