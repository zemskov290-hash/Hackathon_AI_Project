# ADR 0012. Узкий классификатор в маршруте

- Статус: принято
- Дата: 2026-11-19

## Контекст

Сильный вызов нужен, чтобы собрать картину, варианты и стратегию. Тип утверждения, список уже существующих id и выбор навыка — другие задачи: ответ обязан быть одной меткой из закрытого списка. Ошибочный «факт» без ссылки `[S…]`, `[E…]` или `[A….метрика]` нельзя оставлять только потому, что модель так написала.

У этого репозитория нет обязательного ключа API. Рабочий вход — подписка Cursor и `agent -p`. Платный OpenAI-совместимый вызов остаётся вторым контуром, как в ADR 0002, и без ключа не выполняется.

## Решение

`python scripts/strat.py classify` и MCP `strat_classify` размечают три задачи:

- `claim-type` — `fact`, `hypothesis`, `forecast`, `synthetic`;
- `impact` — существующие `E…` и `D…` проекта или `none`, дальше обычные `impact` и `propose-revision`;
- `route` — навык из `skills/`.

Ответ — JSON с `label`, `confidence` и `rationale`. Метки вне списка нет: команда завершается ошибкой и не подставляет ближайшую. Уверенность ниже порога `0.75` или противоречие правилу (факт без ссылки, синтетика без «синтетическ», прогноз без «прогноз») вызывает сильный контур. В `log.md` пишется, что выбрал дешёвый контур, почему метка исправлена и какая стоимость. Оценка по `config/model-prices.json` в поле `cost` журнала не кладётся: в тексте есть «оценка, не счёт».

Порядок в `config/routing.json`: по умолчанию `classifier.backend` равен `rules`. Дальше, если человек переключит backend, идут cursor-agent и OpenAI-совместимый API.

Правила сеть не открывают. cursor-agent, когда его включают, зовётся так: `-p --trust --output-format json --workspace <пустой каталог>`. Флагов `--force` и `--mode ask` нет: ask ищет по кодовой базе, force разрешает команды. Каталог `--workspace` не удаляется. Зависшее дерево гасится: на Windows `taskkill /T /F` и объект задания, на остальных системах сигнал группе процессов. Лёгкая модель — `composer-2.5-fast`, пустой `strong_model` — модель CLI по умолчанию, в списке учётки это `auto`. `--approve-mcps` не передаётся.

Живой архив `bench/classify/runs/20261119T214026Z`, 36 примеров, 0 ошибок вызова. Оценка по `config/model-prices.json`, не счёт. Строка «пересчёт по архиву» — не новый прогон: те же сохранённые ответы, другое правило выбора.

| Контур | Верно | Точность | Среднее время, с | Оценка стоимости, не счёт |
| --- | --- | --- | --- | --- |
| Правила | 33/36 | 0.9167 | 0.000 | 0.000000 |
| Лёгкая composer-2.5-fast | 31/36 | 0.8611 | 16.787 | 0.024372 |
| Модель по умолчанию auto | 29/36 | 0.8056 | 16.066 | 0.504867 |
| Сначала дешёвая, потом сильная | 32/36 | 0.8889 | 17.750 | 0.076845 |
| Правила, модель только при уверенности ниже 0.75 (пересчёт по архиву) | 31/36 | 0.8611 | 4.706 | 0.063580 |

Пересчёт такой: если уверенность правила не ниже 0.75, метка правила. Если ниже — читается лёгкий ответ из архива. Если он расходится с правилом, читается и ответ модели по умолчанию. Метка моделей берётся, только когда они совпали. Иначе остаётся правило. На этом архиве в каждом таком споре модели совпали, поэтому сильный ответ метку не изменил.

Промахи по id. Правила под них не переписывались.

- c09, claim-type. Текст: «Автор заметки считает цену вторичной, опора [E002].» Золото hypothesis. Правила, лёгкая и auto сказали fact из-за скобки [E002]. «Считает» — оценка автора, не цитата факта. Спорный пример.
- c10, claim-type. «Синтетика здесь означает учебный пример, не живого клиента.» Золото hypothesis. Правила оставили hypothesis: в тексте нет подстроки «синтетическ», уверенность 0.58. Обе модели сказали synthetic. Золото совпало с буквой правила, не с бытовым смыслом слова.
- c11, claim-type. «Фактом это станет только со ссылкой [S001].» Золото hypothesis. Правила и auto сказали fact из-за [S001]. Лёгкая модель увидела «станет только» и дала hypothesis.
- i04, impact. «Источник S002 обновился.» Золото [E001]: у E001 источник S002. Обе модели сказали none, квадратной ссылки в тексте нет.
- i07, impact. «Подписка стоит 399 рублей в месяц.» Правила совпали словами с E002, уверенность 0.72. Обе модели сказали none.
- i09, impact. «Гипотеза E003 больше не держится.» Правила и лёгкая модель взяли E003. auto сказал none и потребовал скобки [E003].
- r13, route. «Посчитай среднее по CSV.» Золото 03-collect. Правила не нашли фразу навыка и с уверенностью 0.42 упали в 01-brief. Обе модели назвали 03-collect. Единственный промах правил, который модели закрыли.
- r14, route. «Что дальше по проекту?» Золото и правила — 01-brief, тот же слабый дефолт. Обе модели ушли в 06-strategy. Запрос размытый.

Специализированный оценщик (в config имя `jev`) — четвёртый, необязательный адаптер того же HTTP. `specialized.enabled` по умолчанию `false`. Ключ `STRAT_JEV_API_KEY` без этого флага вызов не включает. Отдельного пакета нет.

`check`, цитаты и скорер `scripts/bench.py` не ослаблены. Классификатор не пишет свидетельство и не закрывает этап. Навыки сбора, синтеза и пересмотра зовут его там, где раньше тип и список id выбирались сильным текстом.

Замер — `scripts/classify_bench.py`. Учебный набор из 36 вымышленных примеров лежит в `bench/classify/items.jsonl`. Живой прогон — архив `bench/classify/runs/20261119T214026Z`. CI гоняет `summary --check`: он пересчитывает таблицу по архиву и по учебным ответам и не вызывает модель. Скорер строк живого прогона не менялся ради вывода ниже. Строка «пересчёт по архиву» читает те же jsonl другим правилом выбора.

Источник строк — `docs/classifier-benchmark.md` и `bench/classify/summary.json`.

## Последствия

Оставляем классификатор. По умолчанию стоят правила.

На живом архиве правила 33/36, лёгкая модель 31/36, модель по умолчанию 29/36, каскад «сначала дешёвая, потом сильная» 32/36. Пересчёт «правила, а модель только если уверенность правила ниже 0.75» дал 31/36 и оценку 0.063580 против нуля у одних правил. Каскад не окупился: модели совпали в споре и ошиблись на c10, i07 и r14, где слабое правило было верным, и починили только r13.

Оговорка о смещении: набор и правила писал один автор, поэтому точность правил завышена. Примеров 36, доверительного интервала нет. Правила под промахи этого прогона не переписывались.

`classifier.backend` остаётся `rules`, пока новый архив не обгонит правила. Вызов cursor-agent по умолчанию не делается. Чтобы мерить модель снова, в config ставят `"backend": "cursor-agent"`. Имя `composer-2.5-fast` — стартовое, его меняют, если `agent --list-models` его не показывает.
