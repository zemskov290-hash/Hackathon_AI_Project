# ADR 0004. Почему ролей три, а не рой

- Статус: принято
- Дата: 2026-11-04

## Контекст

Соблазн хакатона — завести агента на каждый этап. Каждый тащит весь контекст, прячет, кто принял решение, и не делает вывод проверяемее.

## Решение

Ведёт один агент по `AGENTS.md`. Отдельные роли только там, где у них другой контракт выхода:

- researcher — дешёвая модель, только JSONL свидетельств, без стратегии;
- critic — сильная модель, сильнейшее возражение на каждый вариант, без выбора победителя;
- respondent — синтетическая персона, первая строка `TYPE: synthetic`, никогда не факт.

В IDE без субагентов те же файлы из `.claude/agents/` читаются и исполняются в основном чате. Роль respondent существует не ради «ещё одного интеллекта», а как замок: реплику нельзя отмыть до интервью.

## Последствия

Меньше пересказа одного и того же брифа. Пробел — researcher не обойдёт десятки сайтов быстрее человека с хорошим поиском IDE, если поиск в IDE и так есть. Поэтому на малом числе источников роль не вызывают.
