# Сравнение с исходным способом: агент, обычный чат, аналитик

Здесь только измеренные числа. Чего не измеряли, стоит «—» с причиной. Оценщик не подставляет результаты, рубли не выдаются за счёт.

## Что сравниваем

- **Обычный чат с ИИ** — тот же вход (бриф и материалы) одним запросом в чат без этого репозитория, без CLI, навыков и проверок. Это главный «исходный способ» из задания.
- **Аналитик вручную** — только если человек реально засёк своё время на том же кейсе. Иначе строки нет: оценку «аналитик сделал бы за N часов» мы не выдумываем.

## Как закрыть пробелы (10–15 минут)

1. Открыть новый чат Cursor **без** этого репозитория (пустая папка), вставить тот же бриф и материалы одним сообщением, засечь время, сохранить ответ в `chat-case/response.md`.
2. Записать замер в JSON (только реальные числа; токены — если IDE их показывает):

```json
{"label": "обычный чат", "seconds": 0, "input_tokens": null, "output_tokens": null, "check_errors": null,
 "missed": ["что чат пропустил: нет снимков источников, числа без происхождения, …"]}
```

3. Сводная таблица — тот же расчёт для обеих сторон:

```text
python scripts/bench.py case-cost projects/<проект-агента> --chat chat-case/measure.json --rub-per-1m-in <цена> --rub-per-1m-out <цена>
```

Без цены за миллион токенов колонка рублей остаётся «—». Цена, если её задали, печатается как допущение. Аналитик — `--analyst analyst.json` (`{"hours": …}`) и `--analyst-rub-hour`, только по реальному замеру.

## Ограничения

- Один прогон на режим, без доверительного интервала.
- Метрики считают строки и файлы, а не смысл; судья — не языковая модель.
- Время агента зависит от модели и нагрузки сервиса; это не бенчмарк скорости между машинами.
